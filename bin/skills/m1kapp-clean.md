`npx m1kkit stats`(내부적으로 fixearly)가 낸 점수를 근거로, **동작을 바꾸지 않고** 코드를 정리한다.
목적은 등급 숫자가 아니라 **다음에 이 코드를 고칠 때 드는 비용**을 줄이는 것이다.

---

## 먼저 — 고치지 말아야 할 때

작업을 시작하기 전에 이 넷을 확인한다. 하나라도 걸리면 **그 항목은 건너뛴다.**

1. **동결된 저장소** — 리포트 상단에 "이 저장소는 지금 고칠 이유가 없다"(최근 6개월 변경 0건)가 뜨면
   손대지 않는다. 변경 비용은 변경이 일어날 때만 발생한다.
2. **`안정` 태그가 붙은 항목** — 그 파일은 최근에 아무도 안 만졌다. 복잡해도 리팩터 ROI가 낮다.
3. **선언적 마크업** — `cog ≤ 5`인데 길기만 한 함수(OG 이미지, 공유 카드, 랜딩 히어로).
   분기가 없는 JSX 트리는 쪼개도 읽기가 안 나아진다. 스타일 상수와 데이터를 props로 릴레이하느라
   오히려 결합만 는다. **실측: 긴 함수 목록의 약 절반이 여기 해당한다.**
4. **평평한 가드 파이프라인** — 리포트에 `분기 대부분이 빠져나가는 가드 절이다(NN%)` 가
   붙은 항목. `if (!url) return 400;` 이 여덟 줄 늘어선 요청 핸들러가 전형이다.
   cog 는 이걸 3단 중첩과 같은 점수로 매기지만, 가드는 하나씩 읽고 잊으면 되므로
   머리에 안 쌓인다. 헬퍼 뒤로 숨기면 요청 생명주기가 오히려 안 보인다.
   고칠 게 있다면 가드가 아니라 **그 뒤 본문의 중첩**이다.

> 지표는 언제나 뭔가를 지적할 수 있다. 도구가 일감을 만들어내게 두지 마라.

## 점수 구조 (규칙 v7 · 100점 감점제 · 캡 기준 배점)

| 축 | 배점 | 내용 |
|---|---|---|
| **함수 길이** | **23** | 40줄 초과(JSX 60줄) 비율 16 · p90 3 · 상위10 평균 4 |
| **인지 복잡도** | **37** | cog15+ 12 · cog25+ 12 · p90 9 · 상위10 평균 4 |
| **중복** | **9** | 8% 초과분만. 70개 코퍼스에서 점수와 상관 −0.11 |
| **파일 크기** | **8** | 평균 줄 5 · 200줄+ 비중 3 |

**우선순위가 예전과 바뀌었다.** 옛 스킬은 "① 중복 제거"부터 시켰지만, 중복은 배점 9점에
대부분의 저장소에서 0점 기여다(롱테일 — 소수만 크게 맞는다). 지금 실제로 점수를 가르는 건
**함수 길이**와 **복잡도 분포**다.

**분포 항이라는 점이 중요하다.** 최악 함수 하나를 고쳐도 거의 안 움직인다 —
상위 10개 평균을 쓰기 때문에 **여러 개를 실제로 줄여야** 내려간다.

**그리고 점수가 안 움직이는 게 정상인 구간이 있다.** 대부분의 축은 코퍼스 중앙값까지
유예라, 중앙보다 좋은 저장소에선 이미 감점 0 — 더 좋아져도 뺄 게 없다. 이게 v7 에서
`p90` 항을 6점에서 3점으로 줄인 이유다. 남은 축이 그것뿐이라 순위통계 한 줄이 밀리는
것만으로 점수가 뒤집혔다(실측: cog15+ 함수를 저장소에서 전부 없앴는데 순이익 −1점).

cognitive = 중첩 깊이 가중(SonarSource S3776). `a && b && c`는 1, 5중 중첩 if는 flat if 5개보다
훨씬 비싸다. 즉 **평평하게 펴는 것**이 점수가 되지, 함수만 쪼갠다고 오르지 않는다.

### 점수에 반영되지 않는 진단 (등급과 무관, 그래도 진짜 결함)

`O(n²) 배열 조회` · `루프 안 파일 IO/N+1` · `await in forEach` · `스프레드 누적` ·
`루프 안 new RegExp` · `공유 참조 fill` · `빈 catch` · `타입 위생`.

특히 **O(n²)와 N+1은 n이 실제로 큰지 사람이 확인해야** 의미가 있다. 상수 목록·설정값을
도는 자리면 고치지 말고 그 근거를 적어라. 그래서 점수에서 뺐다.

## Step 0: 진단

```bash
npm run stats:report        # 또는 npx m1kkit stats --report
```

리포트(HTML)에서 이 순서로 읽는다:

1. **동결 배너** — 있으면 여기서 멈춘다.
2. **어디쯤인가** — 같은 체급 오픈소스 안에서 내 위치. 이미 체급 중앙 이상이면 급하지 않다.
3. **무엇부터 고칠까** — **변경 비용 순**(복잡도 × churn)으로 정렬돼 있다. 점수 순이 아니다.
   각 줄의 `점수 영향` 칩을 본다: `점수 무관`이면 등급은 안 오르지만 진짜 결함이라는 뜻이다.
4. **점수 지도** — `이미 지켜낸 축`(감점 0)은 건드리지 않는다.

각 항목의 **[지시문]** 버튼이 그 결함 하나만 고치는 작업 지시문을 준다. 그대로 쓰면 된다.

## Step 1: 고치기 — 우선순위 순

### ① 긴 함수 (배점 최대)

**단, 위 "고치지 말아야 할 때" 3번을 먼저 통과해야 한다.** `cog ≤ 5`면 마크업이다.

- **로직과 렌더를 분리** — 상태·핸들러 뭉치를 커스텀 훅으로. `useXxxGame()`, `useFilters()`처럼
  이름이 자연스럽게 붙으면 옳은 분할이다.
- **상수를 밖으로** — 함수 안에 인라인된 딕셔너리·설정 테이블은 모듈 상수로.
- **독립 단계 추출** — 파싱/검증/변환/포맷처럼 한 덩어리로 이름 붙는 단계.

> **잘라낸 함수에 이름을 붙일 수 없으면 자른 게 아니다.** `Part1`·`Section2`가 나오면 되돌려라.

### ② 복잡도 (cog 15+ / 25+)

리포트가 각 항목에 `깊이 N` 을 적는다. **깊이가 목표지 cog 숫자가 목표가 아니다.**
같은 cog 라도 깊이 2와 깊이 5는 다른 문제다. 위 "고치지 말아야 할 때" 4번(가드 파이프라인)을
먼저 통과했는지 확인하라.

- **조기 반환(guard clause)** — 중첩 if를 `if (!x) return`으로. 깊이가 줄면 cog가 크게 떨어진다.
  주의: 조기 반환으로 편 결과는 cog 가 거의 안 줄 수도 있다(가드도 +1씩 센다).
  그래도 그게 옳은 방향이다 — 깊이가 줄었으면 성공이다.
- **분기 → 데이터** — if/else 체인·switch를 lookup 객체나 Map으로. 효과 최대.
- **`&&`/`||` 체인 → 이름 있는 boolean** — 의미 단위로 묶어 읽기를 낮춘다.

### ③ 중복 (8% 넘을 때만)

**같은 이유로 함께 바뀔 코드만** 합친다. 우연히 닮은 두 모듈에서 공용 헬퍼를 뽑으면
결합도만 오른다. 빌드 타깃별 의도적 사본은 그대로 둔다.

### ④ 파일 크기 (배점 8 — 마지막)

**여기서 점수를 벌 생각이면 그만두는 게 낫다.** 같은 코드를 6파일로 쪼개기만 해도 옛 공식은
+27점을 줬고, 그래서 배점을 8점으로 낮췄다. 파일이 긴 진짜 이유(한 파일에 여러 책임)를
먼저 확인하고, 책임이 실제로 여러 개일 때만 나눈다.

### ⑤ kit 활용

직접 짠 로직이 kit 컴포넌트·유틸로 대체되면 코드 자체가 사라진다 — 점수와 kit 반영율이 함께 오른다.
`--kit` 집계의 `kit 사용: N개 요소`가 낮은데 비슷한 걸 직접 짜고 있으면 후보다.

**금지**: 과추상화(1회용 제네릭 헬퍼, 설정 객체 남발), 동작이 바뀌는 "개선",
테스트 없는 공개 API 시그니처 변경, 지표만 노린 기계적 분할, 쓰레기 헬퍼로 분모 부풀리기.

## Step 3: 재측정 — 변화량으로 증명

```bash
npm run stats:report
```

리포트의 **지난번 대비** 섹션이 전/후를 보여준다(`.fixearly-history.json`에 이력이 쌓인다).

**점수보다 원지표를 먼저 본다** — `긴 함수 661개 → 623개(−38)`, `함수 길이 상위10 평균 372 → 336줄`.
점수는 절대 위치고, 변화량이 당신이 한 일이다. 자기 이력과의 비교라 지표만 건드려서는 안 움직인다.

- 한 사이클(항목 1~3개)마다 커밋. 대량 일괄 리팩터 금지 — 리뷰·롤백이 불가능해진다.
- 점수가 안 올랐는데 원지표가 좋아졌으면 **성공이다**. 분포 항이라 여러 개를 고쳐야 움직인다.

## 주의

- 복잡도가 높다고 전부 나쁜 코드가 아니다. 본질적으로 분기 많은 도메인(상태 머신, SVG 분기,
  집계 크론)은 데이터 테이블화가 안 되면 **그대로 두고 사유를 적는다**.
- `(anonymous)` 함수는 콜백/핸들러다. 이름만 붙여도 추적이 된다.
- 점수는 **한 가지 렌즈**다. 설계·테스트·문서·보안·성능·커뮤니티는 재지 않는다.
  낮은 등급이 나쁜 프로젝트라는 뜻이 아니다.
